**CORS Azure↔Vercel corregido (2026-09-15).** Dos causas reales, ninguna era el código de `Program.cs`:
1. `Cors__AllowedOrigins` en Azure estaba como el string literal `"[\"https://*.vercel.app\"]"` (sintaxis de array como texto plano) — las variables de entorno de .NET no parsean JSON. Corregido al formato indexado: `Cors__AllowedOrigins__0=https://evidence-chain-frontend.vercel.app`.
2. Como el dominio de producción de Vercel es estable (no cambia entre despliegues), **no hizo falta** `SetIsOriginAllowed` ni tocar `Program.cs` — un `WithOrigins` con el dominio exacto alcanza.
Verificado con `curl` simulando preflight real: `OPTIONS /api/v1/evidence` con `Origin: https://evidence-chain-frontend.vercel.app` → `204` con `Access-Control-Allow-Origin` correcto; la respuesta real (`GET` sin token) también lleva el header CORS, con `401` esperado (correcto: no se mandó `Authorization`, no es bug). App Service reiniciado tras el cambio.
**Bug de UX encontrado y corregido en `PendingInboxPage` (2026-09-15).** Oleg probó el conflicto 409 a mano en dos pestañas (una acepta, la otra recibe 409) y reportó que el mensaje de error "desaparecía rápido" junto con el registro, visible solo en la pestaña Network. Causa: el aviso vivía dentro del `<li>` de la transferencia (`rowErrors[transfer.id]`); como un 409 de este endpoint siempre implica que la transferencia ya salió de `Pendiente`, el `invalidateQueries` de `onSettled` siempre la quita de la lista justo después del rollback de `onError` — el `<li>` (y el aviso dentro) desaparecía casi de inmediato. No era una carrera rara, era sistemático. El test existente no lo detectaba porque su mock de `GET` era estático (siempre devolvía el mismo item, sin importar el resultado de la mutación). Corregido: el aviso pasa a estado a nivel de página (`failures`), renderizado arriba de la lista y no anidado en el item, para que sobreviva a la reconciliación — incluye el caso borde de que fuera la única transferencia pendiente (la página no debe caer en el estado vacío sin mostrar antes el aviso). Test reescrito con mock con estado (el `GET` deja de devolver el item tras el 409, como el servidor real) que verifica que el aviso sigue visible aun cuando la lista reconciliada queda vacía. Build, lint y 2 tests en verde. Commit `ab03f2a`.
